# MoE Streamflow Prediction

Code for **A Mixture-of-Experts Deep Learning Architecture for Daily Streamflow Prediction across the Sierra Nevada in California**.

The experiment runner and its configuration are in `runs/`; analysis and plotting
scripts are in `analysis/`. The basin list and prepared data remain at the project root:

```text
MoE_Streamflow_Prediction/
├── runs/
│   ├── run_moe_tau.py
│   └── moe_tau.yml
├── analysis/
│   ├── analyze_moe_tau_experts.py
│   ├── plot.py
│   ├── plot_heatmap.py
│   ├── plot_dataset_distribution.py
│   └── ...
├── processed_data/
├── cdec_nondet_basin.txt
└── neuralhydrology/
```

The prepared data contains `time_series/` (daily NetCDF files) and `attributes/`
(watershed CSV files).

Install the project and its dependencies in your active Python environment:

```bash
python3 -m pip install -e .
```

Reading the prepared NetCDF files requires `netCDF4`, which is included in the
project dependencies. For an existing environment where xarray reports that the
`netcdf4` or `h5netcdf` backend dependencies are missing, install the reader using
the same Python interpreter that runs the scripts:

```bash
python3 -m pip install netCDF4
```

Run commands from the `MoE_Streamflow_Prediction` directory. The runner loads
`runs/moe_tau.yml` beside the script; relative data, checkpoint, and output paths
are resolved from the project root. With the project dependencies installed,
train MoE-tau and evaluate it on the test period:

```bash
python3 runs/run_moe_tau.py
```

The configuration uses `cuda:0`; add `--gpu -1` to use the CPU. New training
runs are saved in `runs/moe_tau_<timestamp>/`. Add `--times 5` to train five runs.
Use the `train` mode for training alone. To evaluate or analyze an existing run,
replace `YOUR_RUN_DIRECTORY` with its folder name:

```bash
python3 runs/run_moe_tau.py train
python3 runs/run_moe_tau.py evaluate --run-dir runs/YOUR_RUN_DIRECTORY --period test
python3 analysis/analyze_moe_tau_experts.py --run-dir runs/YOUR_RUN_DIRECTORY --period test
python3 analysis/plot.py
```

The expert analysis writes to `moe_tau_expert_analysis/`, which some plotting
scripts read by default. The workflows documented below explain which
plots run directly from a checkpoint or prepared data. Other plotting scripts
may require prediction files or training records generated by their associated
experiments. All analysis scripts run as `python3 analysis/<script_name>.py`;
their existing data and output locations remain relative to the project root.

To generate Figure 5's training and testing heatmaps in one figure, run the
heatmap script directly with a trained run folder:

```bash
python3 analysis/plot_heatmap.py --run-dir runs/YOUR_RUN_DIRECTORY
```

It loads the latest saved checkpoint, its `config.yml`, and the training scaler
in `train_data/`. It reads `processed_data/` and computes gating weights for all
14 watersheds in `cdec_nondet_basin.txt`, using the training and testing dates
from the saved configuration. No prior analysis command or generated CSV is needed.
To select an exact checkpoint:

```bash
python3 analysis/plot_heatmap.py --checkpoint runs/YOUR_RUN_DIRECTORY/model_epoch199.pt
```

This uses the 30th and 98th percentiles of observed discharge pooled across all
training watersheds to define low-, mid-, and high-flow regimes. The same thresholds
are applied to the testing set. Each cell averages the daily gating weights in its
regime across watersheds, and both heatmaps share a color scale. Days with missing
or non-finite observed discharge are excluded from regime averages (the previous
plot incorrectly counted missing discharge as mid-flow). Empty regimes are marked
"No samples". The figure is saved to
`output/mean_gate_by_global_qobs_fhv_flv_regime_train_test.png`.

The script excludes sequences with missing or non-finite model inputs from gate
inference and reports the count for each watershed and period. This includes
incomplete history at the start of the prepared record: a 365-day input window
needs 364 preceding days. Those days' observed discharge still contributes to the
global training percentiles, preserving the original threshold calculation;
only finite gate vectors contribute to the heatmap means and sample counts.
It uses the saved training scaler and leaves checkpoint weights unchanged. A
checkpoint containing non-finite weights or a watershed with no usable input
sequences produces an explanatory error.

CPU inference is the default; use `--device cuda:0` for a GPU, `--epoch` to select
a saved epoch from a run folder, `--data-dir` for data stored elsewhere, and
`--output-file` to choose the PNG path. `--checkpoint` also accepts a run folder.
Use `--basin-file` to select a different set of watershed IDs for both periods.

For Figure 6's monthly hydroclimate comparison of ISB, NML, and YRS, run directly:

```bash
python3 analysis/plot_dataset_distribution.py
```

It reads the observed data in `processed_data/time_series/` directly. No checkpoint,
training scaler, configuration file, intermediate analysis CSV, or prior analysis
command is needed. The default date range is **2013-01-01 through 2018-12-31**,
matching the current experiment's test period used by the previous workflow.
It averages daily observations by calendar month across the selected years,
skipping missing values separately for each variable. Discharge and precipitation
remain in mm/day; mean daily temperature is `(tmax_x + tmin_x) / 2` in degrees C.

To use a different date range, for example the full prepared record:

```bash
python3 analysis/plot_dataset_distribution.py --start-date 1987-10-01 --end-date 2018-12-31
```

Use `--watersheds` to change the selected names or IDs, `--data-dir` for prepared
data stored elsewhere, and `--output-dir` to change the output location.
The script saves the three Figure 6 panels under `output/`:
`selected_watershed_monthly_climatology_discharge.png`,
`selected_watershed_monthly_climatology_precipitation.png`, and
`selected_watershed_monthly_climatology_temperature.png`.

For the individual watershed expert-usage panels in Figures 7 and 8, run
`plot_selected_watershed_expert_usage.py` directly with a trained checkpoint:

```bash
python3 analysis/plot_selected_watershed_expert_usage.py --checkpoint runs/YOUR_RUN_DIRECTORY/model_epoch199.pt --watershed YRS
```

The checkpoint's run folder must contain its saved `config.yml` and `train_data/`
normalization files. The script reads `processed_data/`, computes the mean expert
gating weights, and creates one PNG per invocation. No analysis CSV or prior
analysis command is required. It uses the test dates saved in the run configuration
and CPU inference by default; use `--period train` or `--period validation` for
other periods and `--device cuda:0` for GPU inference.

Both `--run-dir` and `--checkpoint` accept a run directory and select its latest
saved `model_epoch*.pt` file. Add `--epoch` to select a particular saved epoch:

```bash
python3 analysis/plot_selected_watershed_expert_usage.py --run-dir runs/YOUR_RUN_DIRECTORY --watershed SCC
python3 analysis/plot_selected_watershed_expert_usage.py --run-dir runs/YOUR_RUN_DIRECTORY --epoch 199 --watershed FOL
```

The heatmap, expert-usage, and Spearman scripts also recognize the original model name
`moe_lstm_attn_learnable_temp_gating` in saved run configs, allowing checkpoints
from before the rename to load without editing their config files.

Use ISB, NML, and YRS for Figure 7, and YRS, FOL, and SCC for Figure 8; assemble
the individual images in Overleaf. Watershed IDs such as `4` for YRS are also
accepted. Figures are saved as
`output/single_watershed_expert_usage_<watershed>_<period>_<checkpoint>.png`.
Use `--output-dir` to change the destination or `--data-dir` for prepared data
stored elsewhere.

To plot the relationship between watershed data distributions and expert usage,
run `plot_spearman.py` directly with a checkpoint or run folder:

```bash
python3 analysis/plot_spearman.py --run-dir runs/YOUR_RUN_DIRECTORY
```

This creates separate figures for ISB, NML, and YRS. To create just one figure,
select its reference watershed:

```bash
python3 analysis/plot_spearman.py --checkpoint runs/YOUR_RUN_DIRECTORY/model_epoch199.pt --watershed YRS
```

The script loads the saved `config.yml` and training scaler from the checkpoint's
run folder, reads `processed_data/`, and computes gating weights for all 14
watersheds in `cdec_nondet_basin.txt`. Each reference is compared with the other
13 watersheds. The x-axis averages KS distances for observed discharge, daily
precipitation, 7- and 30-day precipitation totals, and mean temperature. The y-axis
is the L1 distance between normalized mean expert-weight vectors. The Spearman
correlation is printed for each reference.

No earlier analysis command or generated CSV is required. Figures and their
automatically computed comparison tables are saved to
`output/ks_distance_vs_expert_l1_distance_<watershed>_<period>_<checkpoint>.png`
and the corresponding `.csv`. Defaults are the saved test period and CPU inference;
`--period`, `--device`, `--epoch`, `--data-dir`, and `--output-dir` work as in the
expert-usage script. Use `--basin-file` to change the comparison set, including the
reference watershed and at least two others. The label-placement dependency
`adjustText` is included in the project dependencies; for an existing environment,
install it with `python3 -m pip install adjustText`.

`runs/moe_tau.yml` is the only project experiment configuration.
The runner reads it for training and saves the resolved configuration in each run
directory for evaluation. Its optional held-out watershed and area-fold helpers
derive their configurations from this same file and write them to `heldout_configs/`.

Training, evaluation, and `analysis/plot_distribution.py` use `processed_data/`
directly. The optional preprocessing scripts `convert_attributes.py`,
`prepare_normalization.py`, and `prepare_periods.py` remain at the project root.
Raw-data preparation helpers require `final_data_stage1_training_val_071824/`,
which is not included here.

The available architectures are listed in `MODEL_REGISTRY` in
`neuralhydrology/modelzoo/__init__.py`. The proposed model uses
`model: moe_tau` and the `MoETau` class in `neuralhydrology/modelzoo/moe_tau.py`.
For runs saved before the rename, set `model: moe_tau` in the run's `config.yml`;
the saved model weights can still be loaded.

This project builds on NeuralHydrology; its original package information and
citation follow.

![#](docs/source/_static/img/neural-hyd-logo-black.png)

Python library to train neural networks with a strong focus on hydrological applications.

This package has been used extensively in research over the last years and was used in various academic publications. 
The core idea of this package is modularity in all places to allow easy integration of new datasets, new model 
architectures or any training-related aspects (e.g. loss functions, optimizer, regularization). 
One of the core concepts of this code base are configuration files, which let anyone train neural networks without
touching the code itself. The NeuralHydrology package is built on top of the deep learning framework 
[PyTorch](https://pytorch.org/), since it has proven to be the most flexible and useful for research purposes.

We (the AI for Earth Science group at the Institute for Machine Learning, Johannes Kepler University, Linz, Austria) are using
this code in our day-to-day research and will continue to integrate our new research findings into this public repository.
